## Implemented foundation, not a complete runtime

- Strict bounded Cell-registration and placement-mutation contracts.
- PostgreSQL Cell catalog, global control history, tenant placement and combined
  append-only mutation history/idempotency receipts.
- Explicit platform `cell:control` capability using the existing grant mechanism;
  Organization ownership does not confer that capability.
- One placement per Organization; initial generation one; same-Cell suspend/resume;
  immutable Cell binding and monotonic generations enforced by database triggers.
- Tenant placement/receipt forced RLS and composite placement reference.
- Canonical request fingerprinting and durable replay of the historical result.
- P04 assignment events in the mutation transaction.
- Authoritative resolver and a shared-lock admission primitive. A snapshot is not
  an execution permit. **Existing domain execution does not yet invoke admission.**

The catalog's irreversible `has_placements` latch is set by the placement-insert
trigger in the same transaction. Since placement deletion/relocation is not a
runtime capability, it prevents retirement of any bound Cell without bypassing
tenant RLS to enumerate other Organizations. Control mutations take a catalog
exclusive lock before Organization arbitration and placement locks. Admission
takes shared catalog and placement locks. This intentionally prioritizes correctness
over control-plane write throughput; it makes no capacity claim.

PostgreSQL shared row locks also consult UPDATE policy visibility. The new tables'
UPDATE policies therefore permit lock visibility while WITH CHECK still requires
the platform capability for actual writes. Tenant USING/WITH CHECK policies remain
unchanged and restrictive. Raw-SQL negative tests verify that an ordinary runtime
transaction cannot update either catalog or placement.

## Migration and rollback boundaries

`20260918_1713-c18a0b1c2d3e_cell_placement_authority.py` adds four tables after
the canonical P17 head `f17a0b1c2d3e`, plus constraints, indexes, policies and
triggers. It extends the existing platform-grant capability CHECK; it does not
grant that capability to any existing user. It inserts no default Cell or placement.

Downgrade removes the new structures and `cell:control` grants. It is validated
only on an isolated disposable database and is destructive to P18 data. It is NOT
a production rollback procedure. Any future deployed rollback requires a separately
reviewed stop/admission/data-preservation plan; prefer a forward corrective migration.
