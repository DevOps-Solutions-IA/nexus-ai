# ADR-0040: Argon2id password credentials

Status: Accepted. Context: P03 owns password credentials. Decision: Argon2id through the argon2-cffi library primitive only — per-password salt, versioned encoded strings, no custom crypto, no reversible storage. Stored rows carry `algorithm`, `parameters` (JSONB: t/m/p) and `password_hash`; `credential_version` is the migration seam (history kept, latest verifies, future work-factor changes re-hash on next successful verify). Passwords are bounded (12–128 code points, configurable, control characters rejected) BEFORE any hashing work, so pathological megabyte inputs are rejected in O(1) and the hasher never sees unbounded input. Passwords are never normalized (the byte sequence is opaque) and never appear in logs, errors, traces, or responses. Unknown-email logins burn a dummy Argon2id verification so unknown-email and wrong-password paths are indistinguishable in content and close in wall-clock cost. Hardened environments reject work factors below t=3 / m=64 MiB at configuration time (fail closed). Consequences: password material exists only as Argon2id hashes at rest and in memory during verification; the adversarial matrix proves no secret reaches responses or logs.
