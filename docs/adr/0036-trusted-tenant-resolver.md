# ADR-0036: Trusted tenant context resolver boundary

Status: Accepted. Context: P03 (authentication) does not exist yet, so a request must not be able to assert `X-Organization-ID: victim` and gain scope. Decision: `TenantContextResolver` is a provider-neutral boundary. The production/staging default (`NullTenantContextResolver`) resolves **no** trusted context — tenant endpoints answer `403 NXS_TENANT_CONTEXT_REQUIRED` until P03 supplies an authenticated implementation. A `HeaderTenantContextResolver` exists for local/test only and configuration (`_hardened_environment_safety`) refuses `NXS_TENANCY__HEADER_RESOLVER_ENABLED=true` outside local/test. `TenantContext` is immutable and serialisable (`to_portable`) so P04 events and P18 cells can carry `organization_id` explicitly. Consequences: P03 binds authenticated principal → allowed Organization → `TenantContext` → `TenantSession` without rewriting P02.
