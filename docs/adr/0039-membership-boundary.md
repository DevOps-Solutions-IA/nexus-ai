# ADR-0039: Organization membership boundary

Status: Accepted. Context: P03 must bind users to Organizations without creating duplicate-active ambiguity or cross-organization enumeration. Decision: one membership row per (organization_id, user_id) pair with a unique constraint — status transitions (ACTIVE → SUSPENDED → REVOKED) mutate that single row, so two active memberships for the same pair are structurally impossible. The table is tenant-owned with forced RLS. A second USING-only policy (`nxs_principal_self`) exposes exactly the caller's own rows when the transaction binds the authenticated principal GUC (`nxs.principal_id`) and NO Organization scope — this is the login path that enumerates the caller's own memberships across Organizations. The policy deliberately has no WITH CHECK, so nobody can create their own membership outside an Organization-scoped write. Membership is the only source of tenant authority: login hints (`organization_id` in the request body) are honored only when present in the caller's own ACTIVE membership rows, and a foreign hint fails identically to bad credentials. Consequences: no privilege inheritance between Organizations (proven in `test_role_from_another_organization_grants_nothing_here`), no cross-org enumeration (`test_membership_listing_shows_only_own_organizations`), and revoked/suspended memberships block both login and refresh.
