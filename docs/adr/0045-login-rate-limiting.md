# ADR-0045: Authentication abuse-control seam

Status: Accepted. Context: P03 needs a bounded brute-force defense appropriate to the current architecture — not the P20 Sentinel platform. Decision: a `LoginRateLimiter` protocol gates the login path with a fixed-window failure counter keyed by SHA-256(normalized email | client IP) — limiter keys carry no personal data. Two backends: a Valkey-backed `CacheRateLimiter` (persistent, cross-process — the production property a brute-force defense needs) and a `LocalWindowRateLimiter` with a hard cap on tracked keys (bounded memory by construction; the deterministic test backend and the degraded-mode fallback). Backend selection is explicit configuration (`auto` prefers cache, `cache` requires it at startup but still degrades to the bounded local counter on runtime failures, `local` is local/test only and REFUSED in hardened environments). The counter records every failed authentication attempt — credential failures, foreign-org hints, membership failures — and resets on success. Consequences: throttling is deterministic and testable (`tests/unit/test_auth_ratelimit.py`, `TestRateLimiting` integration); availability is preserved under cache outage without weakening to an unbounded primitive; P20 Sentinel remains the future home of richer abuse detection.
