# ADR-0033: Runtime and migration database roles

Status: Accepted. Decision: two non-superuser roles. `nexus_migration` owns schema objects and runs Alembic. `nexus_runtime` is the application request runtime: `NOSUPERUSER`, `NOBYPASSRLS`, `NOCREATEROLE`, `NOCREATEDB`, no schema ownership, and per-table `SELECT/INSERT/UPDATE` grants only — never `DELETE` on protected tenant records, never DDL. `infrastructure/postgres/roles.sql` (idempotent, via `scripts.nxs_dbadmin` or compose initdb) provisions them. On startup in staging/production the app inspects `rolsuper`/`rolbypassrls` for its connected role and **fails closed** if it can bypass tenancy. Consequences: a compromised or buggy request path cannot turn RLS off, drop a policy, or read another tenant; superuser database credentials never reach request runtime.
