# ADR-0033: Runtime and migration database roles

Status: Accepted. Decision: two non-superuser roles. `nexus_migration` owns schema objects and runs Alembic. `nexus_runtime` is the application request runtime: `NOSUPERUSER`, `NOBYPASSRLS`, `NOCREATEROLE`, `NOCREATEDB`, no schema ownership, and per-table `SELECT/INSERT/UPDATE` grants only — never `DELETE` on protected tenant records, never DDL. `infrastructure/postgres/roles.sql` (idempotent, via `scripts.nxs_dbadmin` or compose initdb) provisions them. On startup in staging/production the app inspects `rolsuper`/`rolbypassrls` for its connected role and **fails closed** if it can bypass tenancy — and equally fails closed if the check cannot be completed at all (an unverifiable runtime role is a security failure, not a skip). The raised error and logs carry only a safe error type, never raw database connection detail. Local/test may log a warning and continue. Consequences: a compromised or buggy request path cannot turn RLS off, drop a policy, or read another tenant; superuser database credentials never reach request runtime; a misconfigured or unreachable database in a hardened environment blocks startup rather than running unverified.
