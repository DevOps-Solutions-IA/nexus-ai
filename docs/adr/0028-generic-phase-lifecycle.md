# ADR-0028: Generic engineering phase lifecycle

Status: Accepted. Supersedes the P00-specific closure behaviour. Context: the P00 closure hardcoded `next_allowed_execution = NXS-P01` and did not generically replace the current-phase identity, there was no phase-start command, and the execution lock had no CLI. Decision: `scripts.nxs_start` starts any eligible phase (guard, requirement mapping, lifecycle transition, `active_phase`, lock, manifest auto-creation); the closure engine computes the next phase from the registry DAG (`eligible` = not READY, not blocked, all dependencies READY/GO, no conflicting active phase; deterministic tie-break by registry order), replaces the full `current_phase` identity and releases the lock; `python -m scripts.nxs_guard lock {acquire|status|release|recover}` operates the lock. No phase identifier is hardcoded anywhere in the control system. Consequences: P02–P32 start and close through the same mechanism with no source edits; CI, Makefile and toolchain are phase-neutral.
