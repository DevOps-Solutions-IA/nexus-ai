# ADR-0031: PostgreSQL Row-Level Security is the tenant boundary

Status: Accepted. Context: application `WHERE organization_id = ?` fails the moment one query forgets it. Decision: every tenant-scoped table has `ENABLE ROW LEVEL SECURITY` **and** `FORCE ROW LEVEL SECURITY` (owner included), with `USING` and `WITH CHECK` policies binding rows to `nullif(current_setting('nxs.organization_id', true), '')::uuid`. A missing tenant context resolves to `NULL` and therefore to zero rows — never a global fallback. `apply_tenant_rls` / `drop_tenant_rls` migration helpers make this one line per table. Consequences: cross-tenant read, write, insert and delete are blocked in the database regardless of application bugs; proven by a raw-SQL attack suite (`tests/integration/test_rls_isolation.py`).
