# ADR-0044: Authenticated tenant context resolution

Status: Accepted. Context: ADR-0036 reserved the `TenantContextResolver` seam for P03. Decision: `BearerTokenTenantContextResolver` completes it. It reads ONLY the `Authorization: Bearer` token; no header (or a spoofed `X-NXS-Organization-ID` alone) resolves NO context, so P02's 403 `NXS_TENANT_CONTEXT_REQUIRED` contract is preserved for unauthenticated callers. A valid token's `org` claim — minted server-side strictly after membership verification — becomes the `TenantContext(organization_id, source=RESOLVED_IDENTITY)`. The token's signature binds sub/org/sid, so neither tenant nor identity claims can be altered without invalidating the token (proven by tampering tests). The header resolver remains LOCAL/TEST-only and configuration still refuses it in staging/production. Consequences: `organization_id` never comes from headers, bodies, or global fallback; no P02 tenancy code changed; refresh re-validates membership and user status, so suspension/revocation is enforced within the access-token TTL and immediately at refresh; the resolver is stateless (no per-request database hit) — P27 hardening may add per-request session-state checks behind the same boundary.
